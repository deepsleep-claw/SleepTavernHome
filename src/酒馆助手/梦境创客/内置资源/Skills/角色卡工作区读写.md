# 角色卡工作区读写

把当前角色卡视为一个大小写敏感的 POSIX 文件系统。先用 list_directory、search_files 和 read_file 了解现状，再做最小范围的修改。

`read_file` 返回的是带行号的读取视图，例如 `12 | 正文`。左侧行号和 ` | ` 分隔符只是模型定位用的元数据，绝不是文件正文；传给 `write_file`、`apply_patch` 或文本匹配内容时必须去掉这些前缀。大文件默认最多读取 1000 行和 100000 字符；结果出现 `truncated: true` 时，用返回的 `nextOffset` 作为下一次读取的 1 基 `offset`，并配合 `limit` 分段继续。

- `/character/` 是固定角色字段。`identity.yaml` 只读；不要删除其他固定字段文件。
- `/greetings/` 中每个 Markdown 文件是一条开场白，`index.yaml`
  决定名称和顺序。新增文件会自动追加；需要精确排序或命名时同步编辑索引。
- `/worldbooks/<书名>/entries/` 中每个 Markdown 文件是一个条目。正文在 YAML Frontmatter 后；关键字必须保留
  `{ type: text, value }` 或 `{ type: regex, pattern, flags }` 结构。
- `/worldbooks/bindings.yaml` 管理主、附加和聊天世界书绑定。世界书目录改名会同步现有绑定。
- `/worldbooks-global-readonly/` 与 `/context/chat/` 只读，只能用于参考。
- `/skills/index.md` 列出所有启用 Skill。按需 Skill 需要时再读取对应 `SKILL.md` 或 references。

## 搜索约定

- `search_files` 的 `pattern` 默认是普通文本。搜索 `*`、`[name]`、`a+b` 等字符时直接传入，不需要转义。
- 只有需要正则表达式时才设置 `mode: "regex"`，例如
  `{ "pattern": "^#\\s+", "mode": "regex" }`。正则无效时阅读错误信息，修正表达式后重试。
- `glob` 和 `excludeGlob` 只过滤文件路径，例如 `glob: "worldbooks/**/*.md"`；不要把用于路径匹配的 `*`
  当成正文搜索表达式。
- 可以用多个 Glob、大小写开关、完整单词匹配、前后文行数和结果上限缩小范围。探索目录结构优先使用 `list_directory`。
- 工具失败会作为结构化结果返回。读取其中的错误代码、消息与路径，修正参数、换用其他工具或向用户说明；一次可恢复的工具错误不代表任务已经停止。

优先使用 apply_patch 修改已有长文件。修改后重新读取关键片段并搜索相关引用。不要伪造工具结果；完成文件操作后简要说明改了什么和仍需用户决定的事项。
