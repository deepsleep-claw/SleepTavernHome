# 梦境创客前端交接

> 更新日期：2026-08-14
>
> 适用目录：`src/酒馆助手/梦境创客/`

这份说明给接手界面的Agent和人类维护者使用。梦境创客仍处于未发布开发期，因此只维护当前数据契约，不保留旧会话、旧VFS、旧设置或旧DOM结构的兼容分支。

## 1. 它是什么

梦境创客是在SillyTavern页面中运行的独立创作Agent。模型由Vercel AI SDK Core驱动，酒馆普通聊天继续走酒馆自身生成。后端只复用酒馆设置与文件接口，不运行Agent。

会话分两种：

- **角色会话**：绑定一张角色卡，不能使用角色导航工具。
- **全局会话**：无需预先打开角色，可列出、打开和关闭角色；角色变化时工作区动态挂载或卸载。

全局同一时间只运行一个Agent任务。关闭浮窗不停止任务；关闭浏览器页面则一并结束。

## 2. 前端边界

Vue节点必须留在酒馆助手自己的iframe document中。父页面只放窗口外壳、拖拽缩放手柄、悬浮按钮和魔法棒入口。不要把已挂载Vue DOM搬到父页面，也不要移动原始脚本iframe；跨document挂载曾触发第三方插件的焦点监听异常。

业务状态以Runtime为唯一来源：

```ts
const runtime = getDreamCardAgentRuntime();
const state = shallowRef(runtime.snapshot());
const unsubscribe = runtime.subscribe(next => {
  state.value = next;
});
```

实际订阅集中在 `provideDreamCardAgent()`。叶子组件只使用 `useDreamCardAgent()`，不要自行订阅Runtime、直接写酒馆数据，或建立第二套业务状态。

## 3. 当前界面结构

```text
WorkspaceWindow
├─ AppHeader
├─ PrimarySidebar
├─ WorkspaceTabs（桌面端）
├─ HomeView
├─ SessionWorkbench
│  ├─ SessionToolbar
│  ├─ SessionTimeline
│  ├─ SessionComposer
│  └─ SessionSidebar（文件 / Diff / 上下文）
└─ SettingsWorkspace
```

桌面端保留多会话页签。手机端顶部只显示当前角色或全局会话名称，会话列表和关闭入口移到覆盖式侧栏。运行会话的关闭图标变成停止按钮，点击后必须用应用内模态窗确认“停止并关闭”。

会话侧栏默认收起，桌面端可拖到主区域三分之二宽；手机端覆盖会话，不上下挤压。所有可滚动区域预留滚动条槽位，避免展开内容时宽度抖动。

## 4. Agent配置

Agent设置由三页组成：

- **主要**：配置名称与Agent预设。
- **Skill**：逐项/整组开关Skill，并覆盖全量或按需加载策略。
- **工具**：逐项/整组开关Agent可见工具，包括上下文压缩。

内置Agent配置永远读取脚本内置定义，不使用同名缓存；它只读，但可另存为用户配置。每个会话独立绑定Agent配置，会话工具栏可以切换。已有用户消息时切换会提示缓存可能失效。空闲会话实时应用配置变更，运行会话在本轮结束后应用。

不要向普通用户展示 `r1`、`r2` 等内部Revision。开发者模式可以显示步骤ID、哈希与调试信息，但不能改变权限。

## 5. Skill界面

Skill是全局资源，跨角色和会话复用。Skill设置页的加载策略是默认值，Agent配置可以覆盖。除本地内置文件读写规则外，大型内置Skill从资源包运行时下载；未下载时只能显示下载按钮，不能查看、另存或导出。

按钮语义保持统一：

- 只读Skill显示“查看”。
- 可写Skill显示“编辑”和“删除”。
- 所有已下载Skill显示“另存为”和“导出”。
- 导出后再弹出Markdown或ZIP二级选择；Markdown只含主Skill，ZIP含完整资源。

资源编辑器桌面端左右分栏；手机端点文件后打开模态编辑页。不要让Skill弹窗的样式修改影响会话文件侧栏。

## 6. 会话与时间线

时间线严格保留事件顺序。用户消息与最终助手消息在运行块外，思考、过程输出和连续工具调用在运行块内。完成后多工具运行块默认折叠；失败和停止默认展开。流式工具在解析出tool id时立刻出现卡片，参数未完成时显示生成进度。

审批嵌入对应工具卡片底部，不另起一段文字，也不跳去Diff。审批模式为全局设置：手动审批、YOLO、完全权限。模型、Provider、推理强度、联网与Agent配置则绑定会话。

Diff展示已经发生的文件变化，不负责审批。最新一轮的文件卡可以Undo/Redo；消息回退还会隐藏该轮Agent内容。酒馆聊天生成、Swipe与截断不参与Undo。

中途引导使用同一个输入框，并作为带标记的用户消息插入工具结果之后；引导之后的运行过程重新形成折叠分组。

## 7. 当前VFS

```text
/
├─ identity.yaml
├─ character/{definition,greetings,chats,files,temp}/
├─ worldbooks/
├─ regexes/{character,preset-current,global}/
├─ scripts/{character,preset-current,global}/
├─ files/
├─ temp/
├─ skills/
└─ context/environment.md
```

没有角色时不显示 `character/`。所有挂载世界书统一出现在 `worldbooks/`，不再存在只读世界书或library双路径；能无损往返的手动挂载世界书可写。工程只是 `files/` 或 `character/files/` 下带 `project.yaml` 的普通目录。

文件树调用 `list_path`，支持文件/目录信息、递归深度、大小、子项数和筛选。前端不要重新写一套目录推断逻辑。

## 8. 输入区与模型菜单

桌面宽度足够时展示附件、图片、联网、模型、推理、审批和发送；窄屏把次要项收进加号，但联网、模型/推理和审批保留在外。模型与推理使用同一个有动画的多级浮层：主菜单进入模型或推理子页，左上角返回；浮层应从触发器上方展开、箭头对齐、内容左对齐，并根据可视高度再决定滚动。

不要给模型按钮添加没有语义的闪电图标。控件使用矩形主题样式，与审批选择器保持相近高度和宽度。

## 9. 设置页顺序和反馈

设置侧栏中API位于Agent配置之前。主题、开关等纯本地轻量设置应先更新界面，再异步持久化，避免点击后等待网络。Provider的新建入口位于列表上方，列表内容左对齐，删除按钮在每项右侧并二次确认。新建、保存、删除、导入和导出使用酒馆原生Toast反馈。

Provider保存连接信息，模型保存兼容模式和能力。请求标头、附加参数、排除参数统一使用YAML；模型层覆盖Provider层。手机端Provider工具栏不吸顶，避免软键盘占满页面。
