前端重构不需要兼容旧版 UI DOM、CSS 类名或组件内部状态，但 Runtime 的公开行为和用户数据语义需要兼容。

## 3. 运行环境与挂载方式

梦境创客是“酒馆助手脚本”，不是普通网页，也不是 SillyTavern Server Plugin。

当前结构如下：

```text
SillyTavern 父页面
├─ 魔法棒菜单入口                 index.ts 创建
├─ 可拖动悬浮按钮                 index.ts 创建
├─ 浮窗标题栏与缩放手柄           popup.ts 创建
└─ 酒馆助手原始 iframe             保持在原 document 中，仅改为 fixed 定位
   └─ Vue 工作台                  WorkspaceWindow.vue
```

### 绝对不要破坏的挂载约束

- Vue 节点必须继续属于酒馆助手自己的 iframe document。
- 不要把已经挂载的 Vue DOM 移到父页面，也不要把脚本 iframe 移动到新的父节点。
- 父页面只负责窗口外壳、标题栏、缩放区域、悬浮按钮和魔法棒入口。
- 组件样式通过 `teleportStyle` 提供给需要显示在父页面的外壳；工作台本体仍在 iframe 内。

这里不是普通的架构偏好。此前把节点跨 document 挂载会触发第三方插件的焦点监听异常，例如读取不存在的 `activeElement`。如果确实要改变挂载方式，必须先在真实酒馆同时开启常见第三方插件进行回归测试。

### 窗口生命周期

- 打开窗口：创建窗口外壳，在 iframe 内挂载 Vue。
- 再次点击入口：聚焦已有窗口，不重复创建。
- 关闭窗口：只卸载 Vue 和窗口外壳，Agent Runtime 继续运行。
- 重新打开：从 Runtime 的当前状态恢复界面。
- 关闭或刷新浏览器页面：脚本与 Runtime 一同销毁，不要求后台继续运行。
- 手机端：宽度不超过 `720px` 时窗口占满安全可视区域，不允许拖拽和缩放。

## 4. 当前信息架构

根工作台由三层组成：

```text
应用头部
工作区页签
主内容区
├─ 首页 home
├─ 会话工作台 session
└─ 设置 settings
```

### 4.1 应用头部

显示产品名、当前角色名、开发者模式下的辅助信息、当前运行状态和刷新按钮。

角色信息缺失时必须明确提示先打开角色卡。没有角色卡时不能创建会话或编辑角色工作区。

### 4.2 工作区页签

- 首页按钮始终存在。
- 会话页签可以多开、切换和关闭。
- 运行中的会话允许切换，但不允许关闭页签。
- 关闭页签不等于删除会话。
- 页签至少保持约 4～6 个汉字的可辨识宽度，当前最小宽度为 `7rem`。
- Revision（如 `r12`）只在开发者模式显示。
- 设置页签固定在最右侧，不提供关闭按钮。

### 4.3 首页

首页采用类似编辑器欢迎页的结构：

- 当前角色和“新建会话”主操作。
- API 未配置时显示配置入口。
- 最近 8 个会话。
- 会话超过 8 个时显示“全部会话”文字按钮，可展开当前角色的全部历史会话。
- 会话名称默认为第一条用户输入的前 10 个字，也允许用户重命名。

### 4.4 会话工作台

桌面端结构：

```text
会话标题与控制栏
├─ 主会话区
│  ├─ 时间线
│  ├─ 内联审批/确认卡片
│  └─ 输入框
├─ 可拖动分隔条
└─ 默认收起的侧栏
   ├─ 文件
   ├─ Diff
   └─ 上下文
```

侧栏要求：

- 默认收起。
- 桌面端从右侧展开，宽度可拖拽。
- 最大宽度为工作台的三分之二。
- 文件使用可折叠树视图；选择文件后在右侧/下方查看内容。
- Agent 运行时文件编辑器只读；暂停、完成或等待审批时才可编辑 Working Copy。
- 手机端打开侧栏时改为上下布局，不显示桌面拖拽条。

### 4.5 设置

设置使用左侧子导航，包含：

- 常规
- 预设
- API
- Skill
- 存储与清理
- 诊断（仅开发者模式）

移动端设置导航改为横向滚动。

预设、API 和 Skill 已采用相近的资源工具栏、编辑区和底部保存栏。后续应继续统一视觉，但不要把它们合并为同一种数据模型。

## 5. 会话时间线的固定语义

时间线不是普通聊天列表，重构时必须保留事件顺序和折叠层级。

### 5.1 消息类型

`SessionUiItem.kind` 目前包括：

- `user`：用户消息
- `assistant`：Agent 正式输出
- `reasoning`：思考过程
- `tool`：工具调用
- `guidance`：运行中的中途引导
- `status`：运行状态

UI 只负责显示这些项目，不得从已渲染文本反向重建模型上下文。

### 5.2 一轮运行的视觉分组

一轮运行按 `checkpointId` 关联：

```text
用户消息                         外部，始终可见
运行过程块                       可折叠
├─ 思考过程
├─ 中间助手输出
├─ 连续工具调用组
└─ 其它过程状态
正式助手回复                     外部，始终可见
```

- 正常完成后，包含多个过程片段或工具调用的运行块默认折叠。
- 只有一个过程片段且没有工具时保持展开。
- 纯粹只有最终回复时不创建空的运行过程块。
- 失败、停止、上下文耗尽、异常中断的运行块默认展开并显示状态。
- 工具调用无论成功失败都留在运行块内；失败不是独立浮在外面的错误消息。
- 连续工具调用先合并为一个紧凑工具组，工具组内的单项仍可展开。
- 完成状态显示“已运行 X”，耗时按天、时、分、秒取最前两个非零单位；不足一秒显示“不足1秒”。

### 5.3 思考过程

- 思考过程使用可折叠块。
- 流式思考时，折叠状态下仍显示最新三行预览。
- 完成后显示“已思考 X 秒”并默认收起。
- 思考文本不是最终回答，不应使用与助手消息相同的视觉权重。

### 5.4 Markdown

- 用户消息和最终助手消息渲染 GFM Markdown。
- 支持表格、列表、代码块、链接和图片。
- 单独一行的 HTTP 图片地址会转换为 Markdown 图片。
- 外链使用新窗口打开，并带 `noopener noreferrer`。
- 图片使用 lazy loading。
- 工具参数、错误详情和调试数据仍按结构化文本或代码块展示，不套普通消息 Markdown。
- 不要直接把原始正文交给不安全的 `v-html`；统一经过 `renderMarkdown()`。

## 6. 输入、引导、停止与审批

输入区只有一套，不要重新拆成“输入”和“引导”两个窗口。

- 会话未运行时：输入框发送普通用户消息，按钮文案为“发送”。
- 会话运行时：同一个输入框变为中途引导，按钮文案为“引导”。
- 引导追加到当前目标，不替换旧目标。
- 运行时仍可点击停止。
- 如果当前模型步骤已经自然完成，引导会成为下一条带明确标记的用户消息。

审批与确认应以内联卡片出现在会话工作流中，不能自动跳转到 Diff 页或设置页：

- 普通模式：展示候选修改并等待批准。
- YOLO 模式：普通修改自动提交，高危操作仍强制确认。
- 工具高危确认使用 Runtime 提供的确认状态。
- 冲突显示 Base、Current、Agent 三方信息，并允许逐项决定。
- “回退本轮修改”位于对应用户消息之后；回退保留用户消息并回退后续 Agent 内容。

## 7. Runtime 是唯一业务入口

根组件当前通过以下方式获得状态：

```ts
const runtime = getDreamCardAgentRuntime();
const state = ref(runtime.snapshot());
const unsubscribe = runtime.subscribe(next => {
  state.value = next;
});
```

组件拆分后建议抽成一个很薄的 `useDreamCardAgentRuntime()` composable，由根组件建立一次订阅，再用 props、emit 或 provide/inject 分发。不要让每个叶子组件各自订阅 Runtime，也不要再创建一份前端“影子业务状态”。

### 7.1 UI 主要读取的状态

- `currentCharacter`：当前角色身份。
- `active`：当前会话 `SessionView`。
- `sessions`：当前角色的会话索引。
- `sessionStatuses`：已载入会话的即时状态。
- `profiles`、`activeProfileId`：API Profile。
- `presetProfiles`、`activePresetId`：结构化预设。
- `skills`：全局、跨角色、跨会话的用户 Skill 资源。
- `agentConfigurations`、`activeAgentConfigurationId`：预设与Skill开关组的组合配置。
- `busy`：当前是否正在执行阻塞型界面动作。
- `toolConfirmation`：等待用户确认的工具操作。
- `developerMode`、`debugLogs`：开发者显示。
- `storage`：当前角色会话与全局 Skill 的占用。
- `floatingButton`：是否显示悬浮按钮。

角色卡、开场白和世界书是当前会话 Working Copy 中的工作区文件；Skill 不是角色工作区内容，而是全局资源。每套Agent配置独立决定其中哪些Skill会挂载到会话。

### 7.2 UI 可以调用的主要动作

会话：

- `createSession()`、`openSession()`、`renameSession()`
- `send()`、`enqueueGuidance()`、`stop()`、`resume()`
- `approve()`、`resolveToolConfirmation()`
- `undo()`、`undoToUserMessage()`、`redo()`、`resend()`
- `editUserMessage()`

工作区：

- `writeWorkingFile()`、`deleteWorkingPath()`

设置资源：

- `saveProfile()`、`removeProfile()`、`selectProfile()`、`listModels()`
- `savePresetProfile()`、`removePresetProfile()`、`selectPresetProfile()`、`applyPreset()`
- `saveAgentConfiguration()`、`removeAgentConfiguration()`、`selectAgentConfiguration()`、`applyAgentConfiguration()`
- `saveGlobalSkill()`、`removeGlobalSkill()`
- `updateSettings()`

存储：

- `deleteSession()`
- `clearCurrentCharacterSessions()`
- `cleanupCurrentCharacterStorage()`

不要在 UI 中直接写 `extension_settings`、`/api/files`、角色卡或世界书。所有业务写入都必须继续走 Runtime。

## 8. 资源编辑器的既有语义

### 8.1 API Profile

- 字段：名称、接口类型、Base URL、API Key、模型、自定义请求头。
- “获取模型”是用户主动动作；保存不会自动测试连接。
- API 暂无导入导出。
- 编辑已有 Profile 时，Key 与请求头留空代表保留旧值。

### 8.2 预设

- 有多个 Profile。
- 节点支持启用、排序、拖拽、删除和编辑。
- 导入导出格式为 YAML。
- 导入始终创建新 ID，不覆盖已有预设。
- 当前会话固定创建时的预设版本；设置中的修改不会暗中改写正在运行的会话。

### 8.3 Skill

- 用户 Skill 是全局资源，跨角色、跨会话复用。
- 当前仅支持轻量单 Markdown 文件 Skill，不做 references/assets 编辑器。
- 类型为 `full` 或 `on-demand`；是否开启由每套Agent配置自己的Skill开关组决定。
- 导入导出格式为 Markdown 加 YAML Frontmatter。
- 导入始终创建新 ID。
- 修改和删除已有 Skill 需要二次确认。
- 内置 Skill 只读、不可删除。
- 已挂载Skill的新版本从下一条用户消息开始生效；配置开关只影响新会话或明确应用配置的已有会话。

## 9. 当前视觉实现

工作台为深色主题，设计 Token 集中在 `ui/styles/tokens.scss`，同时挂在 `.dca-app`（iframe 内）与 `.dca-floating-window`、`.dca-floating-body-frame`、`.dca-shadow-root`、`.dca-floating-trigger`（父页面外壳）上：

- 背景层级：`--dca-canvas / -surface / -raised / -overlay`。
- 文字层级：`--dca-text / -text-secondary / -text-muted / -text-disabled`。
- 语义色：`--dca-accent / -success / -warning / -danger / -info`，各带 `-soft` 低透明底色变体。
- 结构 Token：`--dca-border / -border-strong`、`--dca-radius-sm/md/lg`、`--dca-shadow-1/2/3`、`--dca-space-1..6`、`--dca-control-h`、`--dca-font-mono`、`--dca-motion-*`。

`ui/styles/base.scss` 提供按钮变体（`dca-btn-primary/-ghost/-danger`、`dca-icon-btn`、`dca-text-link`）、输入控件、`.dca-field`、`.dca-toggle-row`、`.dca-card`、`.dca-badge`（含运行/失败/等待等状态变体）、`.dca-alert`、`.dca-modal`、滚动条、`:focus-visible` 焦点环、Markdown 排版和设置区块骨架（`.dca-section-stack`、`dca-resource-toolbar`、`dca-resource-savebar`、`dca-form-grid`）。所有动画尊重 `prefers-reduced-motion`。

新增颜色或尺寸时先进 Token；所有工作台选择器继续以 `.dca-` 命名并限制在 `.dca-app` 下，避免污染酒馆或其他插件。

父页面上的窗口外壳和悬浮按钮不在 `.dca-app` 内，相关类包括：

- `.dca-floating-window`
- `.dca-floating-titlebar`
- `.dca-floating-resize`
- `.dca-floating-trigger`
- `.dca-floating-body-frame`

修改这些样式时必须同时在桌面、竖屏手机、安全区域和浏览器缩放下检查。

composables 与纯函数：

- `composables/runtime.ts`：唯一 Runtime 订阅；`useDreamCardAgent()` 注入状态与动作；跨组件导航（`workspaceView`、`settingsSection`）、页签集合、`sidebarFocus`（侧栏定位请求）、`skillEditorRequest`（Skill 弹窗请求）都在这里。
- `composables/timeline.ts`：时间线分组、运行块折叠默认值、工具组合并与全部状态文案。
- `composables/format.ts`：时长、日期、字节数、下载等格式化。
- `composables/sidebar-resize.ts`：侧栏宽度拖拽。

后续改动原则：

- 叶子组件只通过 `useDreamCardAgent()` 读状态、调动作，不要各自订阅 Runtime，也不要再建前端“影子业务状态”。
- 时间线分组只改 `composables/timeline.ts` 纯函数，并同步补测试。

## 11. 响应式与可访问性

现有主断点为 `720px`。重构后至少覆盖：

- 360～430px 竖屏手机。
- 720～900px 窄桌面或分屏。
- 1080p 常规桌面。
- 高 DPI、浏览器缩放和 SillyTavern 安全区域变量。

基础要求：

- 所有图标按钮保留 `title` 或 `aria-label`。
- 所有普通按钮显式使用 `type="button"`，表单提交除外。
- 弹窗有 `role="dialog"`、`aria-modal` 和可读标题。
- 键盘可以完成页签切换、关闭、表单保存和弹窗取消。
- 不能只依赖颜色表达运行成功、失败或等待确认。
- 长文件名、会话名、模型名和错误文本不能撑破布局。
- 触控目标建议不小于 40px，手机端不要依赖 hover。
- 动画应尊重 `prefers-reduced-motion`。

目前弹窗尚未实现完整焦点陷阱。如果新增焦点管理，应限制在 iframe 工作台内部，不要查询或控制第三方插件的 DOM。

## 12. 已知前端技术债

- 弹窗位置和大小每次打开都会重新使用默认值，没有持久化窗口 Frame。
- 当前没有截图或视觉回归测试，只有 happy-dom 关键交互测试。
- 工作台的多区域滚动、窄窗口和超长内容仍需要更多真实浏览器覆盖。
- Font Awesome 样式在窗口打开时按需引入；若更换图标体系，需要同时处理父页面外壳与 iframe 工作台。
- 弹窗尚未实现完整焦点陷阱；如新增焦点管理，应限制在 iframe 工作台内部。

这些都是可以改善的方向，但不要为了处理技术债修改 Runtime 数据格式。

## 13. 验收清单

### 自动检查

```powershell
pnpm run test:agent
pnpm run check:agent
pnpm run build
```

至少保留以下自动测试语义：

- 默认隐藏 Revision、默认收起侧栏。
- 文件树可以展开和折叠。
- 连续工具调用合并显示。
- 思考过程和 Markdown 正确渲染。
- 首页最近会话与“全部会话”有效。
- 预设节点可拖拽，Skill 编辑器可打开。
- 运行时同一输入框切换为引导模式。
- 运行中的页签可切换但不可关闭。
- 五步初次引导可以跳过并持久化。
- API 设置可以主动拉取模型，保存文案不宣称测试连接。

### 真实酒馆检查

1. 悬浮按钮可自由拖动，窗口缩放后仍按九宫格相对锚点保持位置。
2. 竖屏手机能看到入口，窗口为安全区域内全屏。
3. 魔法棒入口和悬浮按钮打开的是同一个窗口。
4. 同时开启其它第三方插件时，打开、点击和输入不触发焦点异常。
5. 关闭窗口后 Agent 继续运行，重新打开能看到最新状态。
6. 多个会话页签可以切换；运行中的页签不能关闭。
7. 时间线流式输出、思考、工具、审批和最终回复顺序正确。
8. Markdown 表格、代码块、长链接和图片在窄屏下不溢出。
9. 文件树、大型世界书 Diff 和长会话滚动保持可用。
10. 设置中的 API、预设、Skill 和存储危险操作均有清楚反馈。

## 14. 什么时候需要暂停并沟通

遇到以下情况，不要自行改变产品语义：

- 为了新视觉必须改变 Runtime 的 `SessionView` 或 `SessionUiItem` 数据结构。
- 需要把 Vue 挂到父页面或移动原始 iframe。
- 想把审批、Diff 或错误重新做成会打断会话的全屏流程。
- 想让运行中的页签可以关闭，或禁止切换到其它页签。
- 想把 Skill 改为角色或会话私有资源。
- 想让 UI 直接写角色卡、世界书、`extension_settings` 或 `/api/files`。
- 想引入大型 UI 框架、路由器或第二套全局状态库。

这些都超出了单纯的前端美化与组件重构，应先和项目所有者确认。
