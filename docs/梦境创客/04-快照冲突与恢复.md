# 快照、冲突与恢复

梦境创客不会把整张角色卡粗暴覆盖。提交时会比较三份数据：本轮开始时的Base、Agent得到的Working，以及酒馆此刻的Current。

不重叠的手动修改会自动保留。如果同一路径两边都变了，Diff页会同时列出Base、酒馆当前和Agent版本，由你逐项选择。即使选择Agent版本，也只覆盖Agent实际改动的路径。

玩家从文件侧栏点击保存时，会立即把这一项写进酒馆，并在没有合适检查点时自动建立一个。连续保存会合并进同一张“玩家修改工作区”卡片，避免时间线被零碎操作淹没；开始新一轮Agent任务或切换会话后才结束这组记录。保存失败时卡片保持展开并显示失败状态，修正问题后可以沿用同一组重试。

如果文件在编辑期间被酒馆其它入口改过，界面会明确让你选择保留Current还是采用Player版本。若Agent此时已有候选修改，玩家版本先写入实际数据，再只替换候选中的同一路径，Agent对其它文件的改动仍然保留。玩家保存本身不需要批准，但仍能像普通轮次一样撤销和重做。

删除世界书、调整重要绑定、清空所有开场白、大量删除条目，以及修改或删除已有用户Skill，始终要求人工确认。开发者模式也不能绕过这些保护。Skill属于全局资源库，不随角色卡快照一起撤销或重做。

酒馆测试聊天是一个刻意的例外：聊天楼层、Swipe和聊天自身的世界书绑定会直接写入酒馆，不进入角色卡快照。普通模式的一次授权会持续到当前Agent运行结束；角色Working Copy若有改动，真正生成前仍会先建立并处理一次中途检查点。

每条用户消息下都有“回退本轮修改”。回退后：

- 角色卡与世界书恢复到消息发送前。
- 该轮Agent回复和工具记录从可见时间线隐藏。
- 用户消息保留，可以点铅笔修改后重新发送。
- 玩家修改卡片会随检查点显示为已撤销；未产生新分支前仍可重做。
- 发送新分支前可以继续重做；一旦从旧点重发，后续分支被覆盖，但废弃快照会保留七天。

写入多个资源时按角色字段、开场白、世界书和绑定依次进行。中途失败会逆序回滚并重新读取校验。

Agent运行期间，工具结果、Working Copy和新快照只存在于当前页面内存，不会每一步都上传。整轮完成、停止、失败或进入审批后，才会原子覆盖该会话唯一的压缩JSON文件；角色的会话名称、大小和更新时间记录在另一个轻量元信息文件中。页面意外关闭时，尚未结束的这一轮会被丢弃；重新打开后从上一次完整保存继续。

快照压缩后嵌入所属会话文件，不再产生独立Blob、Manifest、事件分段或Revision碎片。角色元信息、每个会话、全局Skill和托管文件都使用 `DreamCreator` 前缀的稳定物理文件名；酒馆文件接口不接受目录，因此界面中的目录是安全的虚拟映射，而不是把斜杠塞进上传文件名。

“设置 → 文件与存储”按角色展示共享文件、临时缓存和孤立历史版本。清理缓存只删除Temp和可回收版本；全部清理还会删除附件，引用已删附件的旧会话仍可查看但不能继续生成；重置数据才会连同会话、快照和角色索引一起删除。手动删除附件前会列出受影响会话数量，未主动清理的孤立版本默认保留七天，方便Undo/Redo重新接回。
