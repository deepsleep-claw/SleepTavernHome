# API设置与常见错误

梦境创客把API设置分成两层：Provider负责“怎样连接”，模型负责“连接后使用哪个模型、它具备什么能力”。一个Provider可以保存多个模型，例如OpenRouter下可同时配置来自不同厂商、需要不同兼容方式的模型。

## Provider

Provider包含名称、启用状态、接口格式、Base URL、API Key、自定义请求标头和自定义附加参数。接口格式分为OpenAI Responses、OpenAI Chat / 兼容接口和Anthropic Messages；它只决定请求结构，不代表默认服务商，也不会替你填写地址。

填写Key后可以主动拉取渠道模型。拉取是模型管理功能，不是连接测试；保存Provider不会消耗Token，也不会自动请求接口。

## 模型

每个模型保存显示名称、实际模型ID、启用状态、兼容模式、上下文、输出上限、视觉/推理/工具/联网能力、推理强度、采样参数和模型层高级请求设置。模型层设置会覆盖Provider默认值。

兼容模式属于模型，而不是Provider。当前有“标准”和“DeepSeek”两种；同一个渠道可以同时保存不同模式的模型。DeepSeek思考开启或使用“自动”时，温度和Top P的保存值会保留，但不会随请求发送；选择“关闭推理”后会恢复发送。

第一次手动添加模型ID时，梦境创客会按“精确、前缀/后缀、包含”的顺序匹配本地模板并自动应用。模板只是可搜索、可应用的初始值，不是另一层Profile。之后再修改模型ID只更新推荐，不会悄悄覆盖你已经调过的参数。也可以从models.dev补充上下文、输出、视觉、推理与基础工具能力。

会话绑定Provider和模型。删除或禁用对应项后，旧会话打开时显示“未选择模型”，不会遍历并重写所有历史；重新选择后从下一条用户消息生效。当前正在运行的一轮会固定开始时的模型配置。

## 高级请求设置

Provider和模型都能填写自定义请求标头，以及YAML或JSON格式的附加参数：

- 标头名称不区分大小写，模型层覆盖Provider层。
- 附加参数中的对象递归合并；数组与普通值由模型层整体覆盖。
- 模型层的`null`会删除Provider层同名字段。
- `model`、消息、输入、工具、流式开关等核心字段受保护，不能被附加参数覆盖。
- 最终顺序是SDK请求、Provider附加参数、模型附加参数，最后再执行协议与兼容模式转换。

## 导入与导出

Provider可以连同全部模型一起导入、导出。默认导出不包含Key、请求标头和附加参数；选择“包含敏感配置”时会明确警告。导入始终生成新的Provider和模型ID，重名会自动追加数字，不覆盖现有配置。

Key、请求标头和附加参数使用AES-GCM、随机盐和脚本内置固定密码保存。这能避免在酒馆设置中直接看到明文，但它只是可逆混淆，不是安全保险箱。建议只在本地酒馆中使用，并限制Key权限与额度。

常见问题：

- “当前会话尚未选择可用模型”：模型未选择，或绑定的Provider/模型已被删除或禁用。
- 浏览器无法访问接口：通常是CORS。请换用允许浏览器跨域访问的地址，或自行配置本地反向代理。
- 模型列表为空：渠道没有提供兼容的`/models`结果；仍可手动新建模型并填写实际ID。
- 自定义附加参数无效：检查所选YAML/JSON格式，且顶层必须是对象。
- 多个页面同时保存同一设置：梦境创客保持轻量，不提供跨浏览器强一致锁；最后一次完整保存可能覆盖另一页面的并发改动。
- 上下文已满：新建会话、编辑旧消息，或换用更大的上下文模型。
